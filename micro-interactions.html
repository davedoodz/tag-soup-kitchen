Motion/Hairline — micro-interaction system · davidlafond.xyz as built 19 Aug 2026

Ten micro-interactions for the portfolio, on its own components

Every specimen below is the live site's own markup, palette and copy — the same .project-card.tilt buttons, .filter pills, receipts, ticker notes and Spotify widget that src/App.tsx renders today. Nothing here introduces a colour, radius or font the site does not already ship.

The site currently declares motion in exactly two places: .tilt (400ms cubic-bezier(.22,1,.36,1) plus a 280px pointer sheen) and .location-widget (300ms shadow). Everything else — pills, rows, icons, the detail overlay — changes state instantly. These ten demos fill that gap using a token ledger derived from those two observed values, so the additions read as the same hand.

01

Card tilt + sheen

As built · styles.css .tilt + cardTilt.ts · baseline for everything else

Live values

Rotation is capped at 9°, written as --rx/--ry by a rAF-throttled pointermove; the sheen is a 280px radial gradient at --mx/--my. This is the one interaction the site already has, so it sets the vocabulary: pointer-tracked, 400ms to rest, shadow as the only elevation cue.

Trigger
pointermove / pointerleave
Property
transform, box-shadow, sheen opacity
Duration
400ms transform · 300ms sheen
Easing
--ease-out (transform) · ease (shadow)
Reduced
transform:none, sheen removed

Unchanged — documented here so the other nine read against it. Do not add a second card motion; compose inside this one (see 06).

Weight stays 500 in both states, so the pill never re-measures — the row cannot reflow while you scan it. Press compression is the only mechanical cue in the system; it is reserved for controls that commit something.

Trigger

Property
view-transition-name: project-media
Duration
400ms (--dur-card, reuses the tilt speed)
Easing
--ease-out
Reduced

One name, one pair: the clicked thumbnail and the stage image. The name is assigned on click and removed when transition.finished resolves, or the next open would find two elements with the same name and silently skip the animation. Focus is routed to the detail heading either way — with, without, and instead of the transition.

The hook for App.tsx 
function openProject(index, cardEl) {
  const run = () => setOpenIndex(index)         // your existing state change
  if (!document.startViewTransition ||
      matchMedia('(prefers-reduced-motion: reduce)').matches) {
    run(); requestAnimationFrame(() => titleRef.current?.focus()); return
  }
  cardEl.style.viewTransitionName = 'project-media'
  const t = document.startViewTransition(run)
  t.ready.then(() => { /* stage img gets the same name via CSS class */ })
  t.finished.finally(() => {
    cardEl.style.viewTransitionName = ''
    titleRef.current?.focus()
  })
}

09

Ticker drift — hover brakes

Adds to .ticker · today it is a static horizontal scroller
Trigger
always drifting · pointerenter brakes to 0
Property
scrollLeft (float accumulator) · note translate
Duration
28px/s drift · 160ms note lift
Easing
linear (drift) · --ease-out (lift)
Reduced
no drift at all; native scroll only

The accumulator is the whole trick: scrollLeft += 0.3 stalls because the getter rounds the value straight back, so the loop owns a float and writes the rounded result. Braking is a lerp on speed, not a class toggle — the band eases to a stop under the cursor and back up when you leave.

The drift loop 
let pos = 0, speed = 0, frame = 0
const TARGET = 28 / 1000            // px per ms
function tick(now) {
  const dt = Math.min(now - last, 48); last = now
  speed += ((hovering ? 0 : TARGET) - speed) * (1 - Math.exp(-dt / 180))
  pos += speed * dt
  const half = track.scrollWidth / 2
  if (pos >= half) pos -= half      // the list is duplicated once
  track.scrollLeft = pos            // never read it back
  frame = requestAnimationFrame(tick)
}
10

Filter bar condense

Adds to .filter-bar (position:sticky, 70px) · scroll inside the frame
Scroll ↓
Trigger
scroll position, 0 → 120px
Property
height 70→58, hairline fade in, logo scale .78
Duration
scroll-linked (no time)
Easing
linear against scroll
Reduced
animation:none — bar stays 70px

animation-timeline: scroll(nearest) with an @supports ((animation-timeline:scroll()) and (animation-range:0% 100%)) gate, plus a scroll-listener fallback that drives the same registered --condense property for Firefox — both paths use one set of declarations. Height is not a compositor property — it is animated here because the bar is a 3-element row and the alternative (scaling) would distort the pills; the cost is one layout pass per frame on a 70px band.

Adopting this in the app

  1. src/styles.css — paste the motion tokens into :root under the existing colour tokens, then the per-component blocks from demos 02, 04, 05, 06, 08, 09, 10. Nothing above needs a new colour, radius, or font.
  2. src/cardTilt.ts — unchanged. Demo 01 documents it; demos 05 and 06 deliberately animate children so they never contend for the card's transform.
  3. src/App.tsx — three markup additions only: the caption span inside .project-card (06), the second label span in the music widget (05), the ↗ span in each receipt row (08). The view transition (07) is a wrapper around the existing onOpen(index) handler.
  4. One reduced-motion block covers all ten — extend the block that already exists at the bottom of styles.css rather than adding per-component queries.
  5. What was deliberately left out: no scroll reveals on the project grid (the masonry already settles on load and a second entrance would fight it), no page-load animation, no looping motion except the ticker, and no hover effect on the map widget — its shadow-only treatment is correct because a tilt blurs the WebGL canvas.
